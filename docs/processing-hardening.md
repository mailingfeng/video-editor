# 本地处理逻辑加固

本轮目标是提高新安装包的直接分析成本，保持既有处理效果和本地执行方式。属于适度混淆，不提供防逆向或逻辑保密保证。

## 参数与记录

冻结的 `ProcessingPlan` 仅在任务内存中使用。恢复记录保存工作区身份、任务状态与清理信息；历史记录保存用户报告、结果及必要校验信息，两者均不再序列化处理计划或完整参数。

启动时重写历史目录中可识别的普通 JSON 文件，移除旧 `plan` 字段，并按原有规则整理旧日志和异常。保留原始开始／结束时间、结果及报告，不跟随目录或文件符号链接。无法识别的文件保持原样；权限或磁盘错误会记录整理失败，不能声称该文件已清理。启动恢复会清理或重写可识别的旧任务恢复记录。

## 滤镜传递与清理

原生执行器把视频、音频滤镜写入已通过归属校验的任务工作区 `.v.dat`、`.a.dat`，命令行改为 `-/filter:v`、`-/filter:a` 和对应路径。表达式内容与加固前一致，其他编码、输入和输出参数仍在命令行中。

Unix 文件以 `0600` 创建，并通过目录文件描述符创建／删除，拒绝覆盖已有文件或跟随脚本符号链接。Windows 在写入内容前设置不继承的 Owner Rights DACL，并保留已验证目录的句柄。无法设置权限时停止任务，使用现有权限错误提示；不静默退回不受限制的明文文件。需要文件系统支持这些权限语义。

首次收到正数 `frame` 进度表示滤镜已加载，立即删除脚本。正常退出、启动失败及取消由执行器清理；崩溃后由任务恢复清理保留的脚本。恢复仍要求目录身份和归属标记匹配，并拒绝删除任务目录中的其他文件。

单独保留子进程的标准输入，避免 `Child::wait` 提前关闭它。取消先发送退出指令，三秒后仍未退出才强制结束。

## 编译与安装包检查

所有编译进程序的预设模板均在编译时编码、运行时还原，包含当前两种选项及内部保留的旧预设。编码随构建种子变化；种子和还原代码仍在客户端，不能视为加密保护。数值格式与滤镜字符串用加固前的固定样本摘要核对。

Release 使用符号剥离、关闭调试信息、Thin LTO 和单个代码生成单元。安装资源校验增加主程序可读模板检查，并拒绝安装目录中携带 PDB、dSYM 或源码映射文件；第三方授权材料和发布验证记录继续保留。

参考：[FFmpeg 参数文件加载](https://ffmpeg.org/ffmpeg.html#Options)、[Cargo Release 配置](https://doc.rust-lang.org/cargo/reference/profiles.html)、[Windows SetSecurityInfo](https://learn.microsoft.com/en-us/windows/win32/api/aclapi/nf-aclapi-setsecurityinfo)。

## 保护边界

同一用户、管理员或调试器仍可能截取加载前的临时文件、运行时内存与媒体处理调用。脚本删除不等于取证意义上的磁盘擦除。字符串混淆与符号剥离不会阻止熟练分析者恢复处理规则。

以前分发的版本已经携带既有处理规则，本轮不能收回那些信息，也没有删除旧 Release。加固不改变处理效果，不增加任何平台审核结果承诺。
