# 自定义变化模式设计

日期：2026-10-16

状态：对话设计已确认，书面规格待用户审阅；尚未实施。

设计依据：应用 `0.0.1-beta.6`，实现基线 `1c712fd`；上下文文档提交 `46ddef9`。

## 1. 意图与已确认决定

新增“自定义变化”模式。用户通过“设置”弹窗，分别调节视频、声音及编码变化的强度；界面只提供 0～9 档、推荐标记及效果说明，实际参数由原生层映射并按任务冻结。

成功标准是：用户可以控制各项变化、保存常用档位，推荐配置对原视频的布局影响小于“内容变化”，所有输出继续通过与本次处理计划匹配的完整性检查。媒体差异或本地校验通过不代表平台原创审核通过。

已确认的范围与后续修正按以下决定执行：

| 编号 | 决定 |
| --- | --- |
| D1 | 扩展现有内容变化能力，按独立处理项配置；不建立自由排序的效果编排器 |
| D2 | 每项 0～9 档，0 关闭该项；提供推荐档位与恢复推荐 |
| D3 | 推荐前景缩放 2 档、背景模糊 2 档，均弱于“内容变化”；已有其他效果以 5 档对齐当前强度 |
| D4 | 新增且内容变化没有的效果默认 0，包括裁切缩放、画面柔化和变速 |
| D5 | 允许裁切画面边缘，作为可选项，默认关闭；最终输出宽高不变 |
| D6 | 允许整段变速，因此允许时长变化；每任务随机加速或减速，不提供方向选择；首尾裁剪不在本次范围 |
| D7 | 变速默认保持音高；音高变化由独立的变调档位控制；保留视频全部帧及顺序 |
| D8 | 弹窗编辑草稿，保存才生效，取消不改变已保存设置；本机记住档位，不保存实际随机参数 |
| D9 | 同批视频共用档位，逐任务生成并固定参数；批次开始后不可修改设置 |
| D10 | 前景缩放关闭时，背景模糊和前景动态位移不生效，保留其设置供再次开启 |
| D11 | 设置异常有明确回退／报错；非法启动参数必须拒绝，不能默默替换成推荐值 |
| D12 | 保留现有媒体范围、双活动调度、输入保护、校验后排他提交、取消／关闭与参数加固边界 |

最初提出保持原时长，后续用户明确补充允许变速，D6 是最终决定；不能继续把“不改变时长／逐帧时间戳”作为所有自定义任务的不变量。

## 3. 设置项与推荐值

所有字段都是整数档位。`schemaVersion = 1` 固定以下 14 项；增加字段或改变同档位含义时评估配置／预设版本迁移，不能无记录地改变旧设置的解释。

| 分组 | 用户名称 | 字段 | 推荐 | 0 档语义 |
| --- | --- | --- | --- | --- |
| 布局 | 前景缩放 | `foregroundScale` | 2 | 全画幅，不生成独立前景／背景布局 |
| 布局 | 背景模糊 | `backgroundBlur` | 2 | 背景不做模糊，不自动关闭前景布局 |
| 布局 | 动态位移 | `dynamicOffset` | 5 | 前景固定居中 |
| 布局 | 裁切缩放 | `cropScale` | 0 | 保留完整源图边缘 |
| 画面 | 色相变化 | `hue` | 5 | 不附加色相偏移 |
| 画面 | 饱和度变化 | `saturation` | 5 | 不附加饱和度变化 |
| 画面 | 明暗对比 | `tone` | 5 | 不附加主画面亮度／对比度变化 |
| 画面 | 颗粒噪声 | `noise` | 5 | 不注入额外噪声 |
| 画面 | 画面柔化 | `softness` | 0 | 不柔化主画面 |
| 声音 | 变调 | `pitch` | 5 | 不额外改变音高 |
| 声音 | 音色变化 | `timbre` | 5 | 不附加频谱／压缩处理 |
| 声音 | 音量起伏 | `volume` | 5 | 不附加音量包络变化 |
| 节奏 | 变速 | `speed` | 0 | 原速，使用原时间轴校验 |
| 编码 | 编码微调 | `encoding` | 5 | 使用基础转码编码策略，不免除转码 |

“恢复推荐”采用上表，不把所有字段统一设为 5。全部 0 时仍输出经完整校验的基础 H.264 / MP4；不承诺文件字节相同或与输入无损相同。

### 3.1 内部强度映射

以下是首版拟定的映射规范，属于实现目标，不是已完成的媒体校准。实际数值只出现在原生实现、开发测试及必要研发资料中，产品 UI、用户日志、设置 JSON 不展示或保存这些值。

通用记号：`L` 为档位，`w = L / 5`。每个效果使用任务种子推导的独立随机流，`u` 表示固定在本任务内的 `[0, 1]` 值；同一任务更改某个效果的档位不能意外重新抽取其他效果。周期／相位等辅助值也在计划内固定。0 档直接绕过对应效果，不以极小但非零的参数代替关闭。

| 效果 | 首版映射与界限 |
| --- | --- |
| 前景缩放 | 内容变化基准比例 `r₅ = 0.80 + 0.06u`；`r(L) = 1 - w(1-r₅)`，尺寸向下取合法偶数且最少 2 像素。2 档理论线性比例约 92%～94.4%，5 档为基准，9 档约 64%～74.8%。含背景的输出宽高始终等于输入 |
| 背景模糊 | `sigma = w × clamp(min(W,H) × 0.03, 3, 28)`；2 档为基准模糊强度的 40%，0 档不调用模糊滤镜 |
| 背景衬底 | 属于布局而非主画面色彩档位：亮度偏移为 `-0.14w_foreground`，饱和度为 `max(0, 1-0.65w_foreground)`。前景 5 档对齐现有衬底；推荐 2 档衬底更轻，避免大面积明显暗边 |
| 动态位移 | 原画宽高各 1.5% 作为 5 档幅度，乘以 `w`，再限制在可用前景空隙的四分之一内；正弦周期 8～14 秒，初相按任务固定；不借位移额外裁图 |
| 裁切缩放 | 每任务固定居中裁切。每个维度总移除比例 `d = (L/9) × (0.01+0.03u)`，最高总计 4%，不是每边 4%；取合法偶数裁切尺寸后缩放回原尺寸。档位说明明确“可能裁掉边缘字幕” |
| 色相变化 | 基准 `-8+16u` 度与振幅 4 度的缓慢变化一起乘 `w`，周期 8～14 秒；0 档不残留动态偏移 |
| 饱和度变化 | `1+w(0.02+0.10u)`，5 档对齐现有范围 |
| 明暗对比 | 对比度 `1+w(0.03+0.07u)`，亮度 `w(-0.02+0.04u)`；分别相对中性值缩放 |
| 颗粒噪声 | `round(w × n₅)`，`n₅` 为按任务固定的 4、5 或 6；时间变化噪声种子固定。受整数和像素量化影响，相邻档位可能相同，不能承诺每档输出都不同 |
| 画面柔化 | `sigma = w × (0.2+0.3u)`，仅作用于主画面；与背景模糊分开 |
| 变调 | 半音数 `±w(2+u)`，方向按任务固定；逐声道处理，变调自身补偿时长，额外速度只由 speed 决定 |
| 音色变化 | 5 档复用现有高通 45 Hz、低通基值 10000～14080 Hz、压缩比 1.6。非零档高通为 `45w`，低通为 `24000 × (f₅/24000)^w`，压缩比为 `1+0.6w`；其余压缩时序复用现有策略。先重采样到 48 kHz |
| 音量起伏 | 均值 `1-0.10w`、正弦幅度 `0.03w`，周期 7～12 秒；0 档不应用此包络 |
| 编码微调 | 5 档对齐内容变化的 CRF 20～22、GOP 180～320；正档位 CRF 为 `clamp(18+round(w(2+k)),18,26)`，`k∈{0,1,2}`；GOP 从基础策略值向该任务的内容变化目标以 `min(w,1)` 插值、四舍五入取整数且至少为 1。所有非零档的音频码率复用内容变化的策略，不另外随机抽取码率。0 档完全沿用基础转码的码率／GOP 选择，不把“关闭编码微调”解释为复制码流 |

音频保护限幅只在启用声音效果时使用现有防削波策略，并补偿其延迟；不得混入变速、变调之外的隐式速度变化。低分辨率尺寸取整或静音使某项无可测变化时，不虚构效果；布局尺寸取整的误差应在测试中单独考虑。

背景只在前景缩放非零时创建，画面颜色／颗粒／柔化作用于主画面；裁切先作用于源图，之后从同一裁切结果生成前景和同源背景。裁切为 0 时不丢源图边缘。背景模糊 0 不改变衬底布局的其他规则。

### 3.2 变速抽样

速度档位只决定范围，不新增加速／减速选择器。首版采用可精确表达的有理数：

- `L=0` 时 `s=1`。
- `L>0` 时，从整数 `[5L, 10L]` 中抽取 `D`，独立抽取正负号，`s=(1000±D)/1000` 并约分。
- 因此 1 档改变约 0.5%～1%，9 档约 4.5%～9%；整段只用一个 `s`，不作分段或逐帧随机加减速。
- 同档位不同任务不保证速度或完整文件必然不同；要求独立生成、可在任务内复现，不制造无限多唯一输出的承诺。

这些内部边界在书面规格审阅后成为实现的初始校准目标。实现中若实际样本未达到画质、尾部声音或布局验收，应先调整并记录映射／测试依据；不得通过放宽完整性检查交付。涉及默认档位、项目增删或显著变化范围的调整须回到本规格审阅。

## 4. 用户流程与弹窗

### 4.1 入口及布局

处理模式选择增加“自定义变化”，内部 ID 为 `custom-variation-v1`；原两项名称及默认选中规则保持。仅选中自定义时显示“设置”按钮和“已保存设置”／“推荐设置”摘要，不显示实际滤镜、百分比、速度倍数、频率或编码值。

弹窗沿用原生 `<dialog>` 和现有视觉 token，宽度上限 880px、窄视口保留两侧留白；标题与底部操作保持可见，中间分组内容滚动。五组按布局、画面、声音、节奏、编码顺序排列，不建立额外路由或组件库。

每行包含名称、简短作用说明、整数步进滑杆、当前档位和推荐档位标记；档位有明确“0 关闭／9 更强”含义。依赖不满足时标注原因并禁用该行，不清空其值。无输入或批次包含有声／无声混合视频时，仍允许设置声音档位，由各任务决定适用性。

### 4.2 草稿与保存

1. 首次加载从原生层读取已保存设置、推荐值及可用状态；未完成加载前自定义模式不能开始或打开可编辑设置，原有模式照常使用。
2. 打开弹窗复制已保存档位为草稿。“恢复推荐”只修改草稿；点击“取消”、关闭或 Escape 均丢弃草稿，不改磁盘。
3. 点击保存后校验草稿，保存期间禁止重复保存／关闭和启动操作；原生成功响应后更新已保存值并关闭弹窗。
4. 保存失败保留草稿与弹窗，显示可理解的错误，允许重试或取消；不能在磁盘失败时只更新前端并显示成功。
5. 打开弹窗期间主界面开始按钮不可操作，原生层也要串行处理保存与开始的互斥。若外部命令已启动批次，保留草稿但禁用编辑和保存，提示“任务进行中，设置暂不可修改”；允许取消关闭。
6. 运行时禁用设置入口；设置、开始、导入的异步迟到响应继续受挂载代次及请求身份保护。

浏览器预览仅展示 UI，不能读写原生设置或声称已保存。键盘支持原生焦点约束、Escape 取消、关闭后焦点返回；滑杆有名称、档位读数和键盘调节，错误用 alert 呈现。视觉验证覆盖 1280×840、960×680 及 390px 浏览器宽度。

## 5. 数据契约与持久化

### 5.1 公开档位模型

新增 `CustomVariationSettings`：`schemaVersion: 1` 加第 3 节的 14 个必填档位。Rust 与 TypeScript 保持一致；反序列化及运行时校验拒绝缺项、未知项、负数、小数、大于 9、非数字及未知 schemaVersion。不能依赖 TypeScript 类型或 disabled 控件作为唯一检查。

新增 `invalid_settings` 错误码，对用户显示“处理设置无效，请恢复推荐设置后重试。”保存／读写权限错误继续使用合适的现有错误码。错误不附带实际参数和滤镜。字段级档位校验可在弹窗显示，但不回显任意原生错误文本。

| 契约／入口 | 设计 |
| --- | --- |
| `list_presets` | 新增 `custom-variation-v1`，版本 1 |
| `get_custom_settings` | 返回已保存档位、推荐档位、载入状态 `default / saved / recovered` 和必要的用户提示；不返回实际参数 |
| `save_custom_settings` | 接受完整档位配置；原生检查空闲、校验和持久化，返回实际保存成功的档位 |
| `BatchSettings` / `StartJobRequest` | 增加可省略的 `customSettings`；自定义模式必须显式提供合法值，其他模式拒绝非空自定义值，不静默忽略 |
| `QueueSnapshot` | 增加可省略的 `activeSettings: {presetId, customSettings?}`；批次运行时为真实冻结的公开选择，空闲时省略；不含实际参数 |

可选字段使用 `serde(default, skip_serializing_if = "Option::is_none")` 兼容旧请求／快照；旧 fixture 往返结果保持不变，另增带自定义设置的新 fixture。单任务兼容入口同样支持并校验新模式，但不改变其独占运行约束。

批次开始在状态锁内完成整份档位验证、冻结和任务预留；任何非法配置都不能留下部分运行队列。执行任务只从冻结请求取档位，不在补位时读取磁盘上的最新设置。前端选择、重挂载与事件恢复使用 `activeSettings`，不能用记忆设置猜测当前批次；它随队列结构版本一起合并。

### 5.2 本地设置

设置保存在 Tauri 应用数据目录的 `custom-variation-settings.json`，与 `job-records/` 分开，内容只有 schemaVersion 和档位；不保存种子、实际抽样值、命令行、输出路径或媒体信息。

- 文件缺失：使用推荐值，属正常首次启动，不提示损坏。
- 文件不是合法配置、超过 16 KiB、是符号链接或无法安全读取：本次使用推荐值，返回 recovered 和“已恢复推荐设置，请检查后保存”的提示；不自动覆盖或删除异常文件。
- 用户显式保存：先校验，再在同一应用目录写唯一临时文件、同步并原子替换；拒绝符号链接／重解析目标，清理本次创建的临时文件。持久化成功后才更新内存保存值。
- 写入、权限、空间或替换失败：返回失败，保留之前的有效设置；不记录保存成功。对于被拒绝的非普通目标，提示检查应用数据目录，不绕过检查强行覆盖。
- 保存与开始受同一服务状态锁协调；小型设置写入期间不得让开始跨过空闲检查。保持当前服务已有的短小本地记录写入模式，不引入新配置框架。
- 未知未来 schema 不作猜测性迁移；通过显式保存合法 v1 可替换普通旧文件。将来升级版本时需另定迁移规则。

配置载入状态和提示属于界面信息；可设置独立的错误处理模块，但不新增文件系统插件或允许任意读写路径的 IPC。

## 6. 处理计划与变速校验

### 6.1 责任划分

| 单元 | 单一职责及依赖 |
| --- | --- |
| 自定义设置契约与校验 | 验证公开档位，提供推荐配置；不执行媒体，也不映射实际滤镜 |
| 设置存储 | 对应用数据目录进行有限大小的档位读写；不保存运行计划 |
| 自定义预设模块 | 接受源信息、合法档位和 jobId，生成固定处理参数、滤镜及时间策略；复用已有编码／预设基础 |
| 时间轴变换辅助 | 使用有理数计算目标时间戳、时长与预期摘要；支持现有保留策略和自定义整段变速 |
| 设置弹窗及前端 hook | 草稿、保存、依赖提示、真实运行设置恢复；不生成底层参数 |
| JobService／原生命令 | 空闲互斥、配置冻结、传递请求和批次快照，沿用已有生命周期 |

自定义效果使用固定顺序：源图可选裁切并恢复尺寸 → 可选前景／背景布局 → 主画面颜色、颗粒与柔化 → 合成 → 统一时间变换 → 编码。音频按声道进行变调补偿与统一变速，再进行音色、音量和有需要的保护处理，并恢复目标起点。辅助周期以最终输出播放时间为准，避免速度变化后意外改变定义。

旧“内容变化”、轻微变化及四个内部回归预设保持原参数与媒体语义。只提取本次必要的复用，不能用大范围重构顺带改变旧方案。5 档对齐的是各已有处理项的参数范围与效果，不要求自定义默认输出与旧模式逐字节相同。

### 6.2 整段时间变换

设视频首帧时间为 `v₀`、源时间为 `t`、固定速度为 `s=P/Q`，视频和音频统一采用：

```text
T(t) = v₀ + (t - v₀) / s
目标视频时长 = 原视频时长 / s
目标音频时长 = 原音频时长 / s
目标音频起点 = v₀ + (原音频起点 - v₀) / s
```

视频起点保持 `v₀`；音画原有间隔按相同比例缩放，不能分别清零视频、音频后假定同步。保留所有帧及顺序，VFR 的各帧间距按相同比例缩放；不以重复／丢帧换取固定输出帧率。

计划增加明确的时间策略：`Preserve` 与 `UniformSpeed`。只有自定义且 speed 非零使用后者；现有模式及自定义 speed=0 继续原时间轴摘要校验。源信息保持不可变，目标时间轴不能覆盖源身份或源探测结果。

对于 speed 非零，采用能精确表示有理数变换的输出时间基。源时间基为 `A/B` 时，可选择轨道 timescale `B×P`，目标相对整数 ticks 为 `Δpts×A×Q`，起点 ticks 为 `sourceStartPts×A×P`；编码器／容器统一使用该目标精度。检查分母、整数乘法和底层表达式精度；不能表示时在执行前明确失败，不回退成原速，不容许用宽泛误差隐藏重复时间戳。

现有源摘要只存原时间戳的哈希，不能直接反推出目标摘要。因此校验阶段对同一输入进行受身份保护的流式时间轴扫描，应用同一变换后计算目标相对时间戳摘要，再与输出比较；无需保存完整逐帧数组或写入磁盘。不能只比较总时长而漏检中间帧。

音频按 48 kHz 的目标采样数取整，补偿变调／变速算法及限幅延迟；不重排声道、不混音、不丢尾。仅允许最多一个 AAC 帧（1024 个采样）的末端取整补齐；不以长段补静音凑满目标时长。若实际算法达不到此界限，调整处理策略并补足测试，不放宽该限制。无音轨任务不新增音轨，静音任务不承诺有可听差异。

### 6.3 完整性检查

原生输出验证明确区分源和目标约束：

| 检查 | Preserve | UniformSpeed |
| --- | --- | --- |
| 源身份、输入只读 | 保持现有完整检查 | 同左 |
| 视频帧数与顺序 | 与输入一致 | 与输入一致 |
| 逐帧相对时间戳 | 与源摘要相同 | 与逐帧变换后的目标摘要相同 |
| 平均帧率／时长 | 现有策略 | 依据目标时间轴，不要求原平均帧率不变 |
| 视频起点 | 现有策略 | 保持 `v₀` |
| 音频时长和相对起点 | 现有策略 | 与变换后的目标值比较，考虑有限的编码／采样取整 |
| 尺寸、编码、位深、音轨存在性、声道布局、已知颜色标记 | 现有策略 | 同左；裁切不改变最终输出宽高 |
| 完整解码、输出身份、排他提交 | 全部必须通过 | 同左 |

视频时长／起点的容差依据变换后的平均一帧；音频沿用其与 50 ms 的较大值作为封装检查容差。逐帧摘要仍要求目标精确匹配，末端合成补齐仍受上一节更小的独立界限约束；不能以总时长容差替代采样／尾部验收。保存前成功条件、进度 99% 上限和 `committing` 不可取消规则保持。

## 7. 兼容、异常与保护边界

- 双活动名额覆盖探测、转换、完整校验、提交和清理；自定义的额外时间轴扫描不得提前释放名额。
- 设置保存失败不改变运行任务。单项媒体不支持、时间基溢出或校验失败沿用逐项失败与队列继续语义；非法全批设置在调度前拒绝。
- 同一原生进程重挂载可恢复队列及其冻结公开设置；应用重启只恢复已保存档位和既有最近终态历史，不恢复整个批次或实际运行参数。
- 新滤镜模板同样经过现有编码机制及私有脚本传递；脚本权限和清理策略不降级。JSON 历史／恢复记录继续不包含完整计划、种子或抽样参数。
- 设置加载／保存和快照错误继续清理订阅、拒绝迟到响应；不能使旧任务事件、旧设置回包或保存回包覆盖新批次。
- 每次本地映射的随机性旨在形成受控变化，不是不可推断或防逆向保证。平台审核效果另行按真实输出身份记录。
