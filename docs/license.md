# 使用许可时间

许可有效至北京时间 **2026-12-31 当天结束**，自 `2027-01-01 00:00:00 UTC+08:00` 起到期，对应 Unix 毫秒 `1798732800000`。计算使用固定 UTC 时间戳，不受用户设置的时区影响。

原生 `LicenseService` 同时读取本机时间，并通过 UDP 123 并行查询 `ntp1.aliyun.com`、`ntp1.ntsc.ac.cn`。任一服务器返回有效时间即可参与比较；本机与全部有效网络时间中较晚的时间用于判断许可，收到时间后使用单调时钟继续推进。网络查询每分钟更新，DNS、连接和等待响应共同受每个服务器 2 秒的超时限制。

按 [RFC 5905](https://www.rfc-editor.org/rfc/rfc5905) 检查响应长度、版本、服务端模式、同步标志、stratum、请求回显和非零发送时间戳；忽略无效响应，连接后的 UDP socket 只接受选定地址的响应。网络不可用时采用本机时间和本次运行已确认的较晚时间，并在界面说明回退。不会修改系统时钟。同一次运行中，回调本机时间或后续网络失败不会恢复已到期许可；运行状态不跨应用重启保存。

界面首次查询完成前禁止“开始处理”，每分钟及窗口获得焦点时刷新许可状态，每秒推进到期判断。到期后按钮禁用，悬停及键盘聚焦显示：“使用许可已于 2026-12-31 到期，暂时无法开始处理。请联系软件提供方更新许可。”后端 `start_job` 和 `start_batch` 也使用同一检查，以 `license_expired` 拒绝新任务；后端拒绝时界面立即保持禁用。已启动的批次继续完成，查看视频信息、日志、已保存结果和取消操作不受影响。

这项限制使用本机时钟和普通 NTP 响应，不提供防止程序篡改或离线重启后修改时钟的保证。

自动测试覆盖北京时间截止前最后 1 毫秒及截止时刻、较晚的本机或 NTP 时间、离线回退、回调时钟、慢网络跨越截止时刻、每分钟刷新、无效 NTP 响应、真实本地 UDP 请求与超时，以及界面开着跨越截止时间、查询中禁用、后台拒绝后禁用和卸载时清理监听。
