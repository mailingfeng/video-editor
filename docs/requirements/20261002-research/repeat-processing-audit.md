# 同一原片固定参数重复运行检查

2026-10-10。用户明确要求同一原片多次独立处理后，各次输出都能通过原创审核，并确认内容必须保持基本不变。此前每个处理方案只交付一个版本，不能验证该目标。

## 方法与结果

使用第一组 R3-C 原始冻结命令和同一原片、同一锁定的 Mac Intel FFmpeg，再次处理，仅改变输出路径。FFmpeg 正常退出。原片 SHA256 在重跑后复核未变。

## 实现范围与验收范围

检查时，应用 `src-tauri/src/output/workspace.rs` 将任务 UUID 用在输出文件名和工作目录；`src-tauri/src/presets/basic.rs` 按输入信息和预设生成命令，预设标识写入固定的 comment，当时没有按任务生成的媒体处理参数。此源码检查说明完善前的设计缺少按次变化，不是对所有应用预设都做过重复运行的实测。用户随后要求继续，新增预设的实现与验收独立记录在 [重复处理预设验收](repeat-variation-validation.md)；本报告的 C 固定参数检查结论仍保留。

本次检查直接执行冻结命令，没有走 `JobService`；原 C 的完整媒体校验已经记录在 [组合版验证](round3-combined-validation.md)。此次仅验证 FFmpeg 正常完成、输出哈希一致、输入哈希未变，未重新调用应用完整校验器，也未要求上传这个诊断文件。未修改应用预设、未提交或发布版本。

## 对后续研究的影响

文件名不同、文件字节不同、媒体信号不同、原创审核通过必须分别记录。即便后续建立按次变化，也不能根据本地不同就声称每次审核通过。

现有参考各自来自不同原片，无法识别参考软件的按次变化。需要它对同一原片至少两次独立处理的新输出及各次实际审核结果，成功和失败均保留。用户说既有参考此前上传过而现在未通过，只描述该既有文件的再次提交，不能证明参考软件新生成的版本也无效。后续对照见 [审核证据整理](platform-review-matrix.md)，最终目标与未实现状态见 [需求](requirement.md)。
