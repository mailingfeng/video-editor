# 重复处理实验预设与本地验收

2026-10-10。新增 `repeat-variant-v1`，界面名称“重复处理（实验）”。本轮补充同一原片不同任务采用不同媒体参数的能力，保留用户要求的内容基本不变。用户后续确认两组 A / B 共四份交付视频均未通过原创审核，提示仍是高度相似。任意视频、每次处理均通过的最终目标仍未实现；本地媒体变化不能替代平台结果。

## 处理范围

基于基础转码，在 Y、U、V 三个分量分别加入强度 2 的时间变化均匀噪声。锁定工具中该均匀噪声的整数取值为 −1 或 0；这是滤镜阶段的幅度，不能当作有损编码后的最大像素误差。三组种子由任务 ID 和预设 ID 的 SHA256 推导，冻结到 `ProcessingPlan.args`，沿用现有任务记录和日志。同一任务 ID 可重建相同参数；重现仍需相同输入和工具环境。新任务采用独立推导的参数。

输出保持原尺寸、帧数、逐帧时间轴、镜头顺序和选中音轨的声道布局。音频沿用基础转码，不添加相位、动态音量或高频信号。原有基础、v1、v2 预设和 C2 已通过样片没有追加这项扰动。

当前没有全局输出去重或所有输入的解码画面唯一性保证。参数不同不保证后续压缩仍保留差异，不能用本地变化替代平台原创审核结果。

## 随机种子必须实测

最初使用 `c0_seed` / `c1_seed` / `c2_seed` 时，命令中的种子不同，但真实 MP4 的解码画面完全相同。进一步比较未编码的像素，两个种子的结果仍相同，排除了只由 H.264 量化造成的解释。

锁定 FFmpeg 的 `noise` 初始化会用 `all_seed` 或默认值覆盖分量种子。本轮改为三段滤镜，每段只处理一个分量，并显式提供该段的 `all_seed`。实际解码画面差异测试覆盖这个问题，避免只检查参数字符串不同而误判实现有效。参考 [官方滤镜说明](https://ffmpeg.org/ffmpeg-filters.html#noise) 与 [官方滤镜源码](https://github.com/FFmpeg/FFmpeg/blob/master/libavfilter/vf_noise.c)，结论以锁定二进制的实际测量为准。

## 质量与完整性验收

测试分别将基础转码和两份重复处理输出与同一原片比较。八位 YUV 全帧 RMSE 的预算为：重复处理输出不超过基础转码 RMSE 加 1.0 色阶。不能将两个有损输出之间的误差全部视为新增噪声，编码器不同的比特分配也会影响该差值。

合成动态短片实测基础 RMSE 5.7406，两次输出为 5.7892 / 5.8869；静态灰色视频基础为 0，两次输出为 0.7110 / 0.6402。全范围视频基础为 1.9000，两次输出为 2.1522 / 2.1121；无音轨视频基础为 5.7406，两次输出为 5.8022 / 5.8029。四种输入的 A / B 完整解码画面均不同，均满足质量预算；有音轨的两种输入同时验证音频 PCM 与基础转码完全相同。原有应用完整校验器和容差未修改。

已通过 69 项 Rust 测试、28 项前端测试、5 项生成媒体流水线测试、3 项真实取消 / 恢复 / 冲突测试和 3 项真实批处理测试。新增预设参与 VFR、音画起点偏移、5.1、7.1、无音轨、全范围视频和 WebM 的媒体回归。严格桌面 Clippy 与前端生产构建通过。

提供的 `h264.mp4` 已通过基础、v1、v2 和重复处理四种预设的真实流水线回归，均保留 754 帧、1280 × 594 尺寸和完整时间轴。

## 两份原片的实际应用输出

通过原生 `JobService` 分别导出基础对照、重复处理 A 和重复处理 B。六份文件均先通过应用完整校验再提交，随后重新核对输出探测与原片 SHA256，确认原片未改动。A / B 的全文件、H.264 码流和完整解码画面哈希均不同；同一原片的三份输出 AAC 码流完全一致。

| 第一组 | 720 × 720 / 2990 / 119.6 秒 | 2.0318 | 2.0580 | 2.0591 | 通过，最多增加 0.0273 色阶 |
