# 样本处理 v2：实际应用输出验证

2026-10-09。接续[两组样本差异分析](reference-pairs-analysis.md)，本轮实现独立的 `sample-match-v2` 实验预设，界面名称为“样本处理（相位实验）”，预设版本为 2。基础转换仍为默认，v1 保留用于对照。

两份完整 v2 输出经实际 `JobService` / `NativeRunner` 生成并通过应用的全量解码、规格、逐帧时间轴和输入身份校验。AAC 编码后的音频波形更接近参考视频。2026-10-09 用户反馈两份视频上传后仍未通过审核；该结果说明本轮相位变化不足以实现目标，不能把波形匹配改善当作审核通过的证据。

本次反馈指向下表两份 v2 交付文件；第一组文件名由用户明确给出，第二组依据“两份视频”及上轮交付对应。未取得平台实际接收文件的 SHA256，本次完整审核提示尚未提供。原始本地测量保留，新增反馈见机器可读记录的 `platform_review`。后续独立对照见 [第三轮实验](round3-experiments.md)。

## 本轮参数

唯一的媒体处理差异是将 v1 音频滤镜替换为：

```text
highpass=f=300,lowpass=f=5500,adelay=5:all=1,volume=0.8
```

同一组固定参数用于两份原片，没有逐片调参。高通 / 低通采用工具默认的二阶因果滤波器，延迟约 5 毫秒，增益 0.8；`all=1` 将延迟施加至全部声道。保持 v1 的画面亮度映射、libx264 veryfast / Main、GOP 300、无 B 帧、源视频码率约 1.25 倍及单 / 双声道 AAC 74 kbps。仍保留源尺寸、帧数、帧时间戳、音画起点和声道布局，校验容差没有放宽。元数据标记随预设 ID 改为 `video-editor/sample-match-v2`。

采样率不超过 11 kHz 的输入会在 v2 链前追加 `aresample=48000`，使 5500 Hz 低通处于有效范围。实际 8 kHz AAC 信号测试发现，未显式重采样时工具仅提示频率无效，任务仍可成功但低通没有按预期生效；8 kHz FLAC 因自动格式转换顺序不同没有触发同样的问题。修正前 AAC 相位误差为 0.413 rad，超过 0.15 rad 的验收上限。两份测试原片均为 44.1 kHz，冻结参数和输出不受这项兼容性修正影响。

完整冻结参数、输入 / 输出 SHA256、任务 ID、校验策略与校验结果见[机器可读记录](evidence/phase-v2-measurements.json)。记录中的 `${REPO_ROOT}` 仅替换本机仓库路径前缀，其余参数值与顺序来自应用保存的任务计划。

动态增益、额外高频信号、第二组的 ultrafast / CRF 编码配置属于后续独立实验，本轮没有加入。

## AAC 编码后的音频比较

将实际输出和参考解码为 48 kHz 双声道 float32 PCM，取左右声道算术平均，在共同样本长度内计算 Pearson 相关系数。下表的零时差相关没有做时间对齐或增益拟合；RMS 比值是候选 / 参考。残差另用最优标量增益拟合后计算均方误差 / 参考均方值。

| 指标 | 第一组 v1 | 第一组 v2 | 第二组 v1 | 第二组 v2 |
| --- | ---: | ---: | ---: | ---: |
| 零时差相关系数 | −0.0111 | **0.8556** | −0.0212 | **0.8330** |
| RMS 比值 / dB | +0.0206 | −0.7530 | −0.6827 | −1.8959 |
| 增益拟合后归一化残差 | 99.99% | 26.80% | 99.95% | 30.61% |

v2 左 / 右声道相关系数分别为第一组 0.8553 / 0.8552、第二组 0.8323 / 0.8322。2、30、60、100 秒起点的两秒局部窗口中，v2 对参考的最佳绝对相关时移为第一组 0 ms，第二组 0–0.0208 ms。

本轮还发现，前一轮的“v1 纯滤镜 PCM”指标不能直接代表实际 MP4：两组实际 v1 AAC 波形相对该纯 PCM 对照均提前约 6.979 ms，局部对齐后的相关很高。v1 使用 `zero_phase=on` 的 FIR 时间戳补偿，这一差异可能与其时间戳处理有关；尚未单独分离滤镜、编码和封装的贡献。v2 的实际 AAC 对纯滤镜 PCM 最佳时移为 0 ms。因此保留前一轮的纯 PCM 指标作为实验历史，本轮采用实际 MP4 指标验收。

这两个相似度是音频波形指标，不是原创度或审核通过率。v2 仍存在动态增益和其他音频成分的差异。

## 回归与本地构建

- 前端 27 项、Rust 非忽略测试 68 项通过，生产前端构建和严格 Clippy 通过。
- 原生生成媒体测试 4 项、生命周期测试 3 项、批次测试 3 项通过；v1 / v2 均覆盖 VFR、音画起点偏移、5.1、7.1、无音轨、全范围 YUV 和 WebM。
- 对此前报错的 `h264.mp4` 执行只读兼容性测试，基础转换、v1、v2 均成功，保留 754 帧及完整帧时间轴，输入 SHA256 不变。
- 新增无损 7.1 多频音调夹具，经应用处理为 AAC 后，逐声道比较独立二阶滤波理论的相位与幅度，验证延迟施加至八个声道，并检测混音或声道重排。夹具的 LFE 音调低于 AAC 的 LFE 截止频率。
- 同一信号测试还覆盖 8 kHz 单声道 FLAC / AAC 输入，防止格式协商顺序使滤镜静默失效。
- 预设可发现性 / 版本测试、前端 v2 说明测试、原生 v2 测试均在实现前观察到预期失败，再实现通过。
- 浏览器 `http://127.0.0.1:5174/`，1440 × 1000 / 390 × 844：页面身份、非空首屏、无框架错误、无相关控制台错误、预设选择 / 请求 / 批次冻结、保存位置 tooltip 和无横向溢出通过。Browser 插件不可用，使用已有 Playwright；目录选择和批次 IPC 使用测试替身，原生媒体处理另由真实任务服务验证。截图保存在 `/tmp/video-editor-phase-desktop.png`、`/tmp/video-editor-phase-mobile.png`。
- Mac Intel 本地应用构建成功，位置为 `src-tauri/target/x86_64-apple-darwin/release/bundle/macos/帧序.app`。打包资源检查为 `DEVELOPMENT CHECKED`，本机 x64 架构、媒体工具 SHA256 / 版本及资源材料检查通过；没有将其视为已验收发行版。应用版本仍为 `0.0.1-beta.3`，实验预设版本单独为 2；本轮没有公开新 Release 或构建 Windows 包。
