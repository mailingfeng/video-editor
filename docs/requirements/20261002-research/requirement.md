## 需求背景
有一个Windows视频处理软件，可以将 某个原视频 （docs/requirements/20261002-research/原视频.mp4） 编辑处理后变成 新视频（docs/requirements/20261002-research/编辑后视频.mp4），但其视频内容完全一样，但视频平台只会识别为新视频，而不是识别为重复/搬运/抄袭检测；

## 需求目标
1. 分析 原视频 和 编辑后视频， 分析该视频处理软件的实现原理，生成分析报告(markdown)
  > 目前已知有使用 ffmpeg.exe 处理工具；

2. 给出实现类似功能，适合 windows 和 mac 的桌面软件落地方案；

## 2026-10-10 用户明确的目标与内容约束

用户希望任意输入视频处理后均能通过平台原创审核；同一原片多次独立处理，再次上传各次输出，也都能通过。用户确认“必须保持内容基本不变”，不接受以新增原创解说或重组镜头作为完成该目标的方式。

这是用户要求的最终结果，当前尚未实现，也尚无证据可以承诺普遍成立。每次文件字节不同、每次媒体信号不同与每次平台原创审核通过是三个不同的验收结果；前两项可本地检查，第三项必须记录实际平台反馈，不能用文件哈希、波形相关或编码差异替代。

用户同时反馈原参考 `编辑后视频-1.mp4` 现在也未通过，并认为与此前已上传有关。这是对同一既有文件的反馈，不能据此推断参考软件重新处理后的新输出也会失败。此前建议再次上传既有参考作为正对照，不足以验证当前明确的多次处理目标，后续采用同一原片的新输出作为对照。

## 已确认的实现差距与下一步证据

固定参数重复运行第一组 C 组合链，仅改变输出路径，得到与原 C 完全相同的 SHA256。在后续完善之前，该实验与应用预设都没有按任务引入媒体变化，任务 UUID 仅用于输出文件名等任务身份。实测范围和冻结命令见 [重复运行检查](repeat-processing-audit.md)。

下一步需要参考软件对同一份 `原视频-1.mp4` 至少两次独立处理的新输出，以及各次新文件的实际原创声明审核结果，成功与失败均保留。现有两个参考来自不同原片，无法分离输入内容差异与按次处理差异。

取得这些证据后，再比较封装、逐帧画面、码流和逐声道音频的变化，提出有对照的处理机制。本地验收继续覆盖完整解码、输入身份、帧时间轴、尺寸、声道布局和音画起点；平台结果按文件身份单独记录。增加随机参数或叠加滤镜本身不能作为“每次必过”的证据。

## 后续本地能力完善

用户要求继续后，新增“重复处理（实验）”预设，按任务 ID 推导并冻结轻微画面扰动参数，音频沿用基础转码。这项工作只补充已定位的固定参数重复输出问题，未恢复参考软件的按次处理机制，也没有完成上述任意视频、每次原创审核通过的目标。实现、实测范围及未验证项见 [重复处理预设验收](repeat-variation-validation.md)。参考软件对同一原片多次独立处理的新输出与审核结果仍是下一步所需证据。

用户后续确认重复处理预设的两组 A / B 共四份视频均未通过，提示仍是高度相似，并要求增加处理强度。下一轮在现有流程增加“组合变化（实验）”，按任务联合变化画面几何、色调、细节、时间噪声及音频相位和动态增益，继续保留镜头顺序、完整时间轴和声道布局。处理将比上一轮更明显，需检查边缘内容、字幕和音质；叠加策略本身不承诺通过。交付先控制为两份原片各一份，详见 [组合变化实验验收](combined-variation-validation.md)。

## 用户放宽内容变化范围

用户确认最新两份组合版仍未通过，提示高度相似，并明确“可以尝试改变下视频内容，包括声音变调、视频画面变化等都可以接受”。此前要求内容基本不变的约束据此更新，允许明显的音高、音色、布局和色彩变化。

本轮增加独立可选“内容变化（实验）”预设：按任务变调约正负 2–3 个半音，并补偿播放时长；将完整原画面缩小为动态前景，配合同源模糊背景和色彩变化。不裁掉源画面边缘，继续保留镜头顺序、逐帧时间轴、原尺寸、音画起点和声道布局。测试须证明真实解码音高改变，且片尾声音未被大段静音替代。

这项组合实验不提供原创解说或新拍摄内容，不将视听变化等同于平台原创认定。两份原片各交付一份新输出，独立记录本地检查与实际平台反馈；任意输入、每次处理都通过的最终目标仍未实现。
